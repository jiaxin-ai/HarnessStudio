# 项目导出使用说明

项目导出把一个项目里发生过的全部事情打成一个 ZIP 包，留给你事后查看、分析，或者交给别人复盘。网页上的导出和批量命令 `harnessstudio run` 每个任务跑完后自动保存的 `trajectory.zip` 是同一个东西。

## 一、怎么导出

在项目页点 **导出项目轨迹**，选好要不要包含下面四样，再点 **下载 ZIP**：

- **包含屏幕录像**：虚拟机里录下的整段屏幕视频，体积很大（可能几 GB）。不勾选也有每一步的截图和操作记录。
- **包含任务完成时的快照文件**：任务完成时确认并冻结的成果文件，也就是交付的版本。
- **包含任务当前的 D 盘文件**：每个任务工作区现在的全部文件，包括没做完的。
- **包含项目共享盘的文件**：项目共享盘（有虚拟机时是虚拟机里的 F 盘，没接虚拟机时叫“项目公共空间”）里现在的全部文件，包括批量任务清单上传的输入文件。默认跟着上一项走：勾了“任务当前的 D 盘文件”就一起带上，也可以单独勾选或取消。

项目很大时，浏览器会边生成边下载，等下载结束就好；中途关掉页面也没关系，服务器会马上停下，不会一直占着。录像很多的项目，可以点 **导出到服务器目录**，在服务器上直接生成一个文件夹。

## 二、包里有什么

解开后先看最上面的 `README.md`，里面逐项写了每个文件是什么。大致有：

- **任务**：每个任务一个文件夹，里面是任务定义、完成记录（写着由人还是由 Agent 确认，以及每一条检查依据）、网页上的操作和 Agent 改动的文件。
- **项目共享盘**：`shared` 文件夹，放项目共享盘里的文件，结构和盘上一致。批量命令清单里 `files` 上传的输入文件就在这里，`harnessstudio run` 保存的 `trajectory.zip` 默认就带它。
- **对话**：每个对话的全部消息、模型的思考内容、每次工具调用和完整结果、用量，以及**每次发给模型的原始请求和模型的原始返回**，一次都不省略。对话里 Agent 下载或保存的临时文件也在旁边。
- **自主运行**：项目跑过自主模式的，`autonomy` 文件夹里每次运行一个 `run.json`：用的模型和预算、花了多少 token、运行中发生的每一件事、每一个“需要人”的事项和你是怎么处理的、每个子 Agent 做了哪个任务。
- **虚拟机**：用了虚拟机的，有 Agent 在虚拟机里的每次操作、采集到的每一步截图和轨迹，以及（勾选时）录像。
- **时间线**：`timeline/timeline.jsonl` 把上面所有东西按时间排成一条，从头看到尾就是这个项目的完整经过。

## 三、导出“完整”吗

包里的 `project.json` 会告诉你。

- `warnings` 是导出时遇到的问题，每条一句话，说清是哪个对话、哪次模型调用、什么原因。**完整的导出这里是空的。**
- `modelCalls` 统计了全部模型调用：一共多少次、完整的多少次、不完整的是哪些。

常见的“不完整”和原因：

| 你看到的 | 是怎么回事 |
| --- | --- |
| 调用被停止，只记录到停止时 | 那一刻你暂停或停止了运行，或在对话里点了停止。正在进行的那次调用只收到了一半，记下的就是那一半 |
| 导出时还在运行 | 导出的那一刻 Agent 还在工作，包里是到那时为止的内容。等它停下再导出一次就完整了 |
| Studio 在调用进行中重启 | 服务重启时正在进行的调用，只记到重启前 |
| 超过保存上限，只保存了开头部分 | 单次请求或返回超过 128 MB，非常少见 |
| 没有原始请求记录 | 很早以前的对话，那时还没有开始记录原始请求 |

还有一种调用在发出去之前就失败了（模型什么都没收到），它不算不完整，只计个数。

## 四、要注意的

- 原始请求里有 Agent 看到的全部内容（任务文件、网页内容、截图等），导出包请按项目资料的保密要求保管。密钥不会出现在导出包里。
- 记录会一直保留，只有删除对话（删除任务或项目）时才一起删除。删掉的任务不会再出现在导出里。
- 任务文件变化时，Studio 会自动调用模型给文件写一句“提交说明”，这类调用不属于任何对话，不在导出包里。
