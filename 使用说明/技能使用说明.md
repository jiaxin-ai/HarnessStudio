# 技能（Skills）使用说明

技能就是一份写给 Agent 的说明书。你把"这类事该怎么做"写下来，Agent 遇到这类事就会照着做。

## 一、添加技能

点左下角 **技能**，有三种方法：

1. **新建技能**：填名称、简介、说明，点保存。
2. **上传文件夹**：文件夹里要有一个 `SKILL.md`，其他文件（参考资料、脚本）一起上传。
3. **上传 ZIP 或 .md**：一个打包好的技能文件夹，或单独一个 `.md` 文件。

也可以把技能文件夹直接拖到列表里。

## 二、全局技能和项目技能

- **全局技能**：所有项目都能用，但虚拟机里看不到。
- **项目技能**：只在这个项目里用。它们放在项目 F 盘的 `skills` 文件夹里，虚拟机里也能看到（`F:\skills`），在项目文件面板里也能直接增删。**要在虚拟机里运行的技能，必须放在这里。**
- **插件里的技能**：随插件安装，所有项目都能用，在“插件”页面管理（见《插件使用说明》）。
- 名字相同时：项目技能 > 全局技能 > 插件技能。

## 三、在对话里使用

- Agent 会自己判断什么时候用哪个技能。
- 想指定的话，点输入框左下角的 **使用技能** 按钮选一个，或者直接在消息开头输入 `/技能名`，例如：`/gear-check 帮我核对一下这对齿轮`。
- 不想让 Agent 用某个技能，在技能页面把它的开关关掉就行，不用删除。

改完技能后，从下一条消息开始生效。

## 四、SKILL.md 怎么写

开头两行 `---` 之间写名称和简介，下面写说明：

```markdown
---
name: gear-check
description: 核对齿轮参数时使用：检查模数、齿数和中心距是否一致。
---

## 步骤
1. 读取任务文件里的齿轮参数。
2. 用 a = m(z1+z2)/2 计算中心距，和图纸对比。

## 注意
- 长度单位统一用 mm。
```

- **name**：只能用小写字母、数字和连字符，对话里用 `/name` 调用。
- **description**：一句话说清"做什么、什么时候用"，Agent 靠这句话决定要不要用。
- 带脚本的技能，还要写清在哪里运行，见下一节。

## 五、运行位置：平台、沙箱、虚拟机

每个技能都写明它的工作在哪里做：

| 运行位置 | 什么时候选 | 现在能用吗 |
| --- | --- | --- |
| **平台**（不写就是这个） | 只用 Studio 自己的功能：读写任务文件、整理资料、查网页等 | 能 |
| **沙箱** | 要跑脚本，但不需要工程软件，例如 Python 数据处理 | 能（全局、项目、插件技能都可以），见 `沙箱使用说明.md`；沙箱在设置里关掉时，Agent 会告诉你暂时不能运行 |
| **虚拟机** | 要操作工程软件，例如 SolidWorks、AutoCAD | 能，但只限项目技能 |

**怎么设置**：新建或编辑技能时，在“运行位置”里选一个。选“虚拟机”后，再勾上需要的软件环境（不勾表示任何环境都行）。页面会自动写进 SKILL.md。

也可以直接写在 SKILL.md 开头的 `metadata` 里：

```markdown
---
name: step-export
description: 把 SolidWorks 零件导出为 STEP 文件时使用。
metadata:
  runs-in: vm
  environments: [win11-autocad2026-solidworks2025-ansys2024r1]
---
```

- `runs-in`：`platform`（平台）、`sandbox`（沙箱）或 `vm`（虚拟机）。
- `environments`：需要的软件环境，名称和“添加软件环境”里的一样。有几个就写几个，用逗号隔开。

技能页面上每个技能都会显示运行位置。有问题时会用黄字提示，例如：

- “虚拟机看不到全局技能，请放到项目技能”
- “虚拟机平台没有环境 xxx”

## 六、例子：在虚拟机里运行的脚本

下面这个例子的做法在线上 AutoCAD 环境的虚拟机里实际跑通过：用 Python 连上 AutoCAD，读出版本号。

把技能做成项目技能，文件夹里放 SKILL.md 和脚本：

```
F:\skills\acad-version\
├── SKILL.md
└── acad_version.py
```

SKILL.md：

```markdown
---
name: acad-version
description: 检查虚拟机里的 AutoCAD 能否用脚本调用、读出版本号时使用。
metadata:
  runs-in: vm
  environments: [win11-autocad2026]
---

## 步骤
1. 在虚拟机里运行：
   py -X utf8 F:\skills\acad-version\acad_version.py
   AutoCAD 没打开时脚本会先启动它，大约要一分钟。
2. 把脚本输出的每一行原样告诉用户。脚本报错时，把错误原文告诉用户，不要换别的办法。
```

acad_version.py：

```python
import win32com.client

try:
    acad = win32com.client.GetActiveObject("AutoCAD.Application")   # AutoCAD 已经打开
except Exception:
    acad = win32com.client.Dispatch("AutoCAD.Application")          # 没打开就启动它
print(f"AutoCAD 版本：{acad.Version}")
print(f"程序位置：{acad.FullName}")
```

在对话里输入 `/acad-version`，Agent 会这样做：

1. 先看本对话有没有这个环境、正在运行的虚拟机。没有的话，它会告诉你需要哪个环境，问你要不要启动。它不会自己开虚拟机。
2. 有的话，它在虚拟机里运行 `F:\skills\acad-version\acad_version.py`，再把结果告诉你。

## 七、写虚拟机脚本要注意

- **用 `py` 启动 Python，不要用 `python`。** 在 AutoCAD 环境的虚拟机里，输入 `python` 只会提示“去 Microsoft Store 安装”。其实 Python 已经装好了（3.10，可以用 win32com 调用软件），要用 `py` 启动。
- **加上 `-X utf8`。** 虚拟机的命令行默认不能输出中文，脚本一打印中文就会报 `UnicodeEncodeError`。写成 `py -X utf8 脚本.py` 就没问题。
- **用脚本启动的软件默认是隐藏的。** 想在软件区的画面里看到它，在脚本里加一行 `acad.Visible = True`。
- **普通命令最多等 110 秒。** 跑得久的（求解、重建模型、批量导出），Agent 会改用后台运行，见《后台运行使用说明》。
- **只有任务对话里才有虚拟机。** 在项目对话里，Agent 会请你到任务的对话里用这个技能。
- 以上几点是在 AutoCAD 环境里实际测出来的。其他环境（例如 SolidWorks）第一次用之前，可以先让 Agent 在虚拟机里运行 `py --version` 确认一下。
