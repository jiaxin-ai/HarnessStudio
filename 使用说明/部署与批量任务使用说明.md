# 部署与批量任务使用说明

`harnessstudio` 是 HarnessStudio 的命令，只有三个用法：

```bash
harnessstudio                 # 启动：没部署就部署好，打印网址给大家访问
harnessstudio stop            # 停止 Studio（不影响虚拟机）
harnessstudio run tasks.yaml  # 批量跑一批任务
```

第一次安装的步骤见安装包里的 `安装说明.md`。这份说明讲平时怎么用。

## 一、三个命令各做什么

### `harnessstudio`：启动

| 情况 | 它做什么 |
| --- | --- |
| 还没部署过 | 问几个问题，构建，启动，打印网址 |
| 已经在运行，代码没变 | 只打印网址，不重启任何东西 |
| 停着（`stop` 之后） | 启动，打印网址。这期间代码版本变了的话先问，见第七节 |
| 已经在运行，但代码有更新 | **先问你**，见第七节 |

把打印出来的网址发给同事，用浏览器打开就行，不用注册和登录。

启动时它还会检查虚拟机管理服务（vm_manager）。连不上时会提示，Studio 照样启动，只是暂时不能用虚拟机。

这台机器上没有配置 vm_manager 时，Studio 是**无软件模式**：网页上没有软件区，Agent 只用 Linux 沙箱和联网做事。

**接不接虚拟机，第一次部署时就定下来，之后不要再改。** 两种模式把任务文件存在不同的地方（接虚拟机时在 vm_manager 的 projects 文件夹里，不接时在 Studio 自己的数据里），部署以后再切换，原有项目的任务文件就看不见了。要换成另一种，就另起一个实例：在另一个文件夹里再解压一份安装包，第一次用 `HS_INSTANCE=新名字 ./bin/harnessstudio` 启动，端口换一个。步骤见安装包里 `安装说明.md` 第五节的「另起一个实例」。原来的实例和它的项目照常留着。

### `harnessstudio stop`：停止

停止 Studio 的网页服务和沙箱服务。数据都保留，虚拟机不受影响，再运行 `harnessstudio` 就回来了。

### `harnessstudio run`：批量跑任务

有一批互相独立的任务时，把它们写进清单，一条命令跑完。**它不是评测工具**，不打分。每个任务都是一个普通的 Studio 项目，由 Agent 按自主模式做完，之后由你在网页上检查，做得不好的再让 Agent 改。

Studio 没在运行时，`run` 会先把它启动起来；Studio 已经在运行时，`run` 永远不会重新部署它，所以不用担心打断别人正在做的事。

想用另一台机器上的 Studio，加 `--url http://那台机器:3080`。这时只连接、不部署，连不上就报错。

## 二、任务清单怎么写

清单是一个 YAML 文件。安装包里有一份示例 `examples/tasks.yaml`，它用到的输入文件在 `examples/inputs/`。要改的话，把整个 `examples` 文件夹复制出来再改（`cp -r examples ~/我的批量任务`），只复制清单的话，里面的 `./inputs/...` 就找不到了。

**示例里的模型名是我们自己用的**（`deepseek-v4-pro`、`deepseek-v4-flash` 等），先换成你「模型配置」里的模型名，否则命令会提示模型不存在。

清单的结构：

```yaml
defaults:                                   # 所有任务共用的设置
  orchestratorModel: deepseek-v4-pro        # 总 Agent 用的模型
  workerModel: deepseek-v4-flash            # 子 Agent 默认用的模型
  workerModels: []                          # 可选：总 Agent 可以给个别任务换用的模型
  budget: { tokens: 20000000, hours: 2, vms: 1 }   # 每个任务的预算
  parallel: 1                               # 同时跑几个任务
  projectPrefix: "批量"                     # 可选：项目名的前缀
tasks:
  - name: 齿轮校核简报                       # 任务名
    goal: |                                 # 目标
      整理一份……
  - name: 箱体建模
    goal: |
      ……
    files: [./inputs/箱体草图.dwg]           # 可选：输入文件
    budget: { hours: 4 }                    # 可选：这个任务单独的预算
```

| 写什么 | 说明 |
| --- | --- |
| `name` | 任务名，清单里不能重复。结果文件夹用这个名字，网页上的项目名也带着它 |
| `goal` | 目标，和自主模式窗口里的「目标」一样。**写得越具体，结果越好**：要做成什么、做到什么程度、有什么要求和限制。批量时没人回答 Agent 的问题，缺的信息它只能自己假设 |
| `files` | 输入文件，路径相对于清单文件所在的文件夹。会上传到这个项目的共享空间（虚拟机里的 F 盘，沙箱里的 `/shared`）。文件要放在清单所在的文件夹或当前文件夹之内，其他位置的文件读不到，命令会告诉你该放到哪里 |
| 模型 | 必须是「模型配置」里已有的模型，名字完全一致；从示例复制来的清单要先换成你自己的模型名。同名模型在几个 Provider 里都有时，写成 `Provider 标识/模型名`。要操作虚拟机里的软件，子 Agent 需要**支持图片**的模型才能看到屏幕，把它写进 `workerModel` 或 `workerModels` |
| `budget` | `tokens` 是折算 token（什么是折算 token 见《自主模式使用说明》第八节），`hours` 是小时数，`vms` 是同时开的虚拟机数。还可以写 `workers`（同时工作的子 Agent）、`rounds`（总 Agent 轮数）、`cacheReadWeight`（缓存读取的折算比例）。没写的用 Studio 设置页里的默认值 |

清单写错时，命令会一次列出所有错误，带上行号或任务名，**一个任务都不会启动**。拼错的字段名也会报错，不会被悄悄忽略。

## 三、运行时会看到什么

```bash
harnessstudio run tasks.yaml --parallel 2
```

终端里每个任务一行，显示状态、用时、用了多少折算 token、几个子 Agent。全部结束后打印一张汇总表：任务名、结果、用时、折算 token、网页链接。

运行过程中，你随时可以在网页上打开对应的项目，看图谱、看对话，和平时的自主运行一样。

| 参数 | 作用 |
| --- | --- |
| `--parallel N` | 同时跑 N 个任务，默认 1。用虚拟机的任务受服务器资源限制，同时最多约 2 个 |
| `--out 文件夹` | 结果放在哪里，默认 `./harnessstudio-runs/<日期时间>/` |
| `--resume 文件夹` | 接着跑上一次没跑完的，见第六节 |
| `--url 地址` | 用别的机器上的 Studio |
| `--no-video` | 轨迹里不带录屏（录屏可能有几 GB） |

## 四、遇到需要人的情况会怎样

批量时没有人盯着，所以规则是：

- **Agent 提问**：命令自动回答“没有更多信息，请按合理假设继续，并在结果里写明你的假设。”，Agent 接着做。每次自动回答都记在结果里，你可以事后看它问了什么。
- **其他要人处理的情况**：停止这个任务，把它标为**需要人**，写明原因，接着跑别的任务。包括：
  - Agent 报告受阻、需要你动手（登录、许可证、弹窗等）；
  - 子 Agent 卡住了；
  - 预算用完；
  - 服务重启过；
  - 总 Agent 说目标达成了，但还有任务没做完；
  - 总 Agent 出错。

一个任务“需要人”不影响其他任务。停下的任务，项目和已有的文件都保留，可以到网页上接着处理（见第五节）。

命令结束时的退出码：

| 退出码 | 意思 |
| --- | --- |
| 0 | 全部完成 |
| 2 | 有任务需要人，或者失败了 |
| 1 | 命令本身出错（清单写错、连不上 Studio 等） |
| 130 | 被 Ctrl+C 中断 |

## 五、结果在哪里，怎么查看和重做

### 结果文件

```
harnessstudio-runs/20261101-143000/
├── summary.csv          整批的汇总表，可以用 Excel 打开
├── summary.json         同上，给程序读的
├── batch-state.json     续跑用的进度记录，不要改
├── 齿轮校核简报/
│   ├── result.json      这个任务的结果
│   └── trajectory.zip   完整的轨迹
└── 箱体建模/
    ├── result.json
    └── trajectory.zip
```

`result.json` 里最常看的几项：

| 字段 | 内容 |
| --- | --- |
| `status` | `completed` 完成、`needs-human` 需要人、`failed` 失败、`interrupted` 被中断 |
| `reason` | 需要人或失败的原因 |
| `projectUrl` | 这个项目的网页链接 |
| `usage` | 用了多少折算 token 和总 Agent 轮数 |
| `tasks` | 图谱里每个任务的状态，以及是 Agent 还是人确认完成的 |
| `autoAnswers` | 所有被自动回答的问题 |

`trajectory.zip` 是这个项目的完整导出，解开后先看里面的 `README.md`。它包含：每个对话的全部消息、模型的思考内容、每次工具调用和完整结果、用量；每次发给模型的原始请求和返回；自主运行的事件、事项和子 Agent（`autonomy/<运行ID>/run.json`）；合并的时间线；完成记录和依据；提交的文件；用了虚拟机的还有操作日志和录屏。

### 在网页上查看

每个任务是一个项目，名字是 `<前缀> <月-日 时:分> · <任务名>`。点汇总表或 `result.json` 里的链接可以直接打开，也可以在左侧的项目列表里找。

打开后和平时的项目一样：图谱里标着「Agent 完成」的任务由 Agent 确认完成，点开任务能看提交的文件和每一条的检查依据；点右上角的自主模式按钮能打开这次运行的面板；对话里有完整的过程。

### 让 Agent 重做

- **某个任务做得不好**：点开这个任务，点 **继续修改**，在任务对话里告诉 Agent 怎么改。用到它结果的下游任务会进入“待复核”。这和《自主模式使用说明》第七节一样。
- **需要人的任务**：在项目里把问题处理好（例如调高预算、补上缺的资料），然后点右上角 **自主模式** 再启动一次，让总 Agent 接着把剩下的做完。批量命令已经停止了原来的运行，所以要重新启动，不是点“继续”。
- **整个任务要重来**：改好清单里的目标，把它单独放进一份新清单，再 `run` 一次。旧项目保留，要删的话在项目列表里手动删除。

批量跑出来的项目都是普通项目，会一直留在项目列表里，不需要的可以自己删掉。

## 六、中断和续跑

**按 Ctrl+C**：第一次按下，命令停止本次启动的所有任务，尽量导出已有的轨迹，写好结果（这些任务记为 `interrupted`），然后退出，退出码 130。这要等一会儿。再按一次就立即退出，不再等待。

**接着跑**：

```bash
harnessstudio run tasks.yaml --resume harnessstudio-runs/20261101-143000
```

- 已经有结果的任务（完成、需要人、失败）**跳过**；
- 被中断的、还没开始的任务**在新项目里重新跑**，不是接着旧项目做。旧项目保留，结果里会注明；
- 输出继续写在原来的文件夹里；
- 清单和上次不一样时，命令会提示你。

断电或命令被杀掉也一样：进度随时保存在 `batch-state.json` 里，用 `--resume` 接着跑。这种情况下 Studio 里可能还留着没停的运行，到网页上看一下，有的话在运行面板里停止它。

## 七、代码更新后再运行

维护者更新了代码以后，再运行 `harnessstudio`，如果 Studio 正在用旧版本运行，它会**先问你**：

> 检测到代码有更新，重新部署会让正在进行的自主运行暂停，是否继续？

同时列出还没结束的自主运行有几个。

- **回答是**：构建新版本，替换旧版本，并保留旧版本以便回滚。之前进行中的自主运行会变成“已暂停（服务重启）”，到运行面板里点 **继续运行** 就能接着做。虚拟机不受影响。
- **回答否**：什么都不变，继续用旧版本。

**停止以后再启动也会问**：用 `harnessstudio stop` 停掉以后，如果这期间换了新版本的代码，再运行 `harnessstudio` 会问“上次运行的是……，现在要部署……”，默认答“否”。答“否”就按上次的版本把原来的容器原样启动起来。**回滚以后**也一样：回滚之后再运行不带参数的 `harnessstudio`，会先问要不要部署当前源码的版本，默认“否”，所以不会悄悄又更新回去。

**建议**：先看看有没有人在用、有没有自主运行或批量任务在跑，等它们结束，或者提前告诉大家。

`harnessstudio run` 不会替你做这个决定：代码有更新时它只提示一句，继续用正在运行的版本。

每次部署完成时会打印一行回滚方法，新版本有问题时照着执行就能回到旧版本。回滚只换程序，不撤销数据的变化。回滚之前，先在运行面板上停止所有还没结束的自主运行。

## 八、常见问题

- **提示模型不存在**：清单里的模型名要和「模型配置」里的完全一致，大小写也要一样。示例清单里的模型名不一定是你配置的那些。
- **任务一直标为需要人，原因是预算用完**：调高清单里的 `budget`，或者到网页上调高预算后重新启动自主模式。估预算的方法见《自主模式使用说明》第八节。
- **Agent 的假设不对**：说明目标写得不够具体。把假设的内容写进 `goal`，再跑一次。
- **`trajectory.zip` 很大**：录屏占地方。不需要录屏时加 `--no-video`。
- **提示文件不在允许的目录里**：把输入文件放到清单所在的文件夹里，用相对路径引用。
- **网页打不开、连不上**：先在服务器上运行 `harnessstudio`，它会告诉你现在的状态和网址。其他问题见 `安装说明.md` 的常见问题。
